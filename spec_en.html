DocR v1.9.0 Technical Specification & Advanced Reference

This document is the official technical specification and advanced reference for DocR (v1.9.0), a containerized R statistical analysis gateway for Microsoft Excel. It details DocR's internal system architecture, exact statistical and algorithmic specifications across all 13 analytical modules (including R packages, estimators, degrees-of-freedom approximations, and multiplicity adjustments required for academic Methods sections), automated backend preprocessing and fail-safe mechanisms, and custom formula/syntax recipes for power users.

Tip

Introductory GUI Tutorials, Practice Workbook & Ribbon Quick Access For step-by-step introductory instructions ("which cells to select and which buttons to click") and hands-on sample datasets, open the interactive practice workbook DemoBook_en.xlsx (also bundled inside the release ZIP) and watch the tutorial videos on the official distribution page (https://soyogu.github.io/DocR/en.html). You can also open this specification (spec_en.html) anytime directly from Excel by clicking the Manual button on the DocR ribbon (Settings / System group, next to About). This document omits elementary button-by-button walkthroughs to focus on computational foundations and advanced modeling techniques.

Part 1: System Architecture & Common Specifications#

1.1 Local Containerized Architecture & Full macOS Parity (v1.9.0)#

DocR employs a strictly local three-tier architecture connecting Microsoft Excel (frontend UI and worksheet input/output management) to an isolated Linux R execution environment inside a Docker container (backend statistical engine) over local HTTP:

text
[ Microsoft Excel (VBA Add-in: DocR.xlam) ]
        │  JSON over HTTP (http://127.0.0.1:8000)  *100% Local Loopback
        ▼
[ Docker Container: docr-api (Image: r-stat-api / Base: rocker/r-ver:4.3.2) ]
   ├── Port 8000: Python 3 Multi-Threaded Proxy & Live Console Server (/app/server.py)
   └── Port 8001: R 4.3.2 + Plumber REST API Server (/app/api.R) + Pre-Compiled Stan Models
  • 100% Local Execution & Data Confidentiality: All communication takes place exclusively over the local loopback interface (127.0.0.1:8000) on the user's computer. Selected Excel data are never transmitted to external cloud servers or over the internet, enabling secure offline analysis of confidential clinical records, human-resources data, and unpublished experimental datasets.
  • Zero Conflict with Existing Host R Environments: The R 4.3.2 runtime, C++ toolchain (g++ for Stan/brms), morphological dictionaries, and all CRAN packages are fully encapsulated inside the docr-api container. Even if R or RStudio is already installed on the host OS, zero version collisions or package dependency conflicts can occur.
  • Automated Container Startup & Memory Management: Whenever an analysis is launched while Docker Desktop or the docr-api container is stopped, the VBA frontend (EnsureDockerRunning) automatically starts the daemon and container in the background and verifies readiness via GET /ping (with a 1,800-second [30-minute] proxy timeout to support long MCMC runs). At the conclusion of every API endpoint, temporary R objects are explicitly released and garbage collection (gc()) is invoked to prevent memory growth across large datasets or repeated runs.

  • Full Windows & macOS Feature Unification (v1.9.0):

    • Starting in v1.9.0, all 13 analytical modules—including Descriptives (describe), Correlation (correlation), Regularized Regression (glmnet), Bayesian Additive Regression Trees (bart2), and all v1.9.0 diagnostic enhancements—operate with 100% identical specifications across Windows (x86_64) and macOS (Apple Silicon M1/M2/M3/M4 ARM64 and Intel).
    • Apple Silicon (ARM64) Native Support: Latest CRAN dbarts and lme4 source builds are compiled natively inside the ARM64 image, eliminating legacy NEON SIMD vector type-mismatch bugs on Apple Silicon processors.
    • Lossless macOS Character-Encoding Pipeline: To overcome Excel for Mac's internal UTF-16LE memory encoding and AppleScript HTTP transport limitations, DocR implements a dedicated binary bridge (MacCurlPost) combining iconv (bidirectional UTF-16LE ⇔ UTF-8 conversion) with binary curl (--max-time 1800), completely eliminating character corruption in non-ASCII variable names, factor levels, and embedded SVG plot labels (paired on Windows with UTF-8 ADODB.Stream and Win32 8.3 short-path resolution via GetShortPathNameW).
    • macOS UserForm Clipboard Integration: Standard keyboard clipboard shortcuts that Excel for Mac disables inside VBA UserForms are restored via a custom event handler (MacTextBoxHandler), enabling native Cmd + C (Copy) / Cmd + V (Paste) / Cmd + X (Cut) inside all formula and syntax text boxes.

System Requirements (OS, Disk Space & Memory)#

  • OS & Excel: Windows 10 / 11 (64-bit) or macOS (Apple Silicon M1–M4 / Intel) + Desktop Microsoft Excel

  • Storage (Free Disk Space): 10 GB or more of free disk space recommended

    • Release ZIP archive: ~1.1 GB (docr_image.tar inside is ~1.3 GB); loaded r-stat-api Docker image: ~4.3 GB on disk (10 GB+ free space accommodates temporary headroom during ZIP extraction and docker load).
    • Updating DocR automatically deletes previous DocR containers and images before loading the new engine, ensuring disk usage never accumulates across versions.
  • Memory (RAM): 8 GB minimum (16 GB or more recommended, especially for running Docker Desktop alongside parallel MCMC sampling in brms and BART)

1.2 Real-Time R Calculation Console, R Code Output & Ribbon Manual Button#

To eliminate the "black-box" opacity common to GUI statistical software, DocR v1.9.0 provides live visibility into ongoing computations, complete script-level reproducibility, and instant documentation access.

  • One-Click Ribbon Manual Button:

    • Clicking Manual (Japanese UI: マニュアル, Help icon) in the Settings / System group on the DocR ribbon (next to About) opens the Technical Specification matching your active UI language (spec_en.html for English, spec.html for Japanese) directly in your default web browser.

  • Real-Time R Calculation Console (http://127.0.0.1:8000/console):

    • Checking Output R Code in the Settings / System group of the DocR ribbon tab automatically opens the local live console (http://127.0.0.1:8000/console) in the default web browser (checking /console_status first to avoid opening duplicate tabs; checkbox state is persisted inside the add-in).
    • Inside the container, the Python proxy (server.py) captures R's stdout and stderr streams in unbuffered mode (bufsize=0) and streams live updates to the browser at 300-millisecond polling intervals (/logs).
    • Researchers can inspect start/end timestamps, dispatched R commands, live chain-by-chain brms (Stan) MCMC sampling percentages, BART tree sampling and Partial Dependence Plot (PDP) grid evaluations, LCA random-start iterations, and R warnings or error diagnostics in real time.
    • Unchecking Output R Code dispatches a close signal (/console_close) that closes the console window automatically. Even when Output R Code is unchecked, you can manually open http://127.0.0.1:8000/console in any browser during a long computation to monitor live progress at any time.

  • Automated Reproducible R Code Output on Result Sheets:

    • When Output R Code is checked, an [ Executed R Code ] section is automatically appended to the bottom of the output worksheet.
    • Because the code block includes both the Variable Alias Mapping (Safe Internal Name : Original Name) legend and # Original Formula: / # Original Variables: header comments, the executed code can be copied directly into standalone R or RStudio scripts for independent replication, supplementary materials, or further customization.

1.3 Data Ingestion Rules, Type Coercion & Stealth Variable Aliasing#

Range Selection & Non-Destructive Output Principle#

  1. 1st-Row Header Rule: The first row of the selected cell range is always parsed as variable (column) names, and rows 2 onward are ingested as observational records in tidy format (1 row = 1 observation / case). Even if entire worksheet columns (e.g., A:F) are highlighted, DocR automatically intersects the selection with the worksheet's populated UsedRange.

  2. Minimum Data Dimensions & Pre-Flight Validation:

    • Descriptives (describe): 2 rows × 1 column or more
    • EFA/PCA (fa/principal): 3 rows × 2 columns or more (at least 2 observed variables selected)
    • All other analytical modules: 2 rows × 2 columns or more
    • If the selected range contains any Excel formula error (#DIV/0!, #N/A, #VALUE!, #REF!, #NAME?, #NUM!) or any blank header cell in row 1, pre-flight validation (IsDataClean) halts safely prior to API transmission and reports the exact row and column coordinates.
  3. Strict Protection of Source Data: Every analysis writes its output to a newly created worksheet named <Module>_Res_<hhmmss> (e.g., lm_Res_152030), recording the exact source address (e.g., Data Source: 'Sheet1'!A1:E120) in cell A1 and formatting console tables in monospace (Consolas in English UI mode). Original data worksheets are never overwritten or modified.

Automatic String & Numeric Type Conversion Rules#

  • Automatic Factor Conversion of Text Columns: In regression and modeling modules (lm, glm, lmer, glmnet, brms, bart2), text columns (e.g., "Male" / "Female", "Control" / "Treatment") are automatically coerced to R factor (categorical) variables (prepare_dataframe(..., strings_as_factors = TRUE)) and entered via standard treatment contrasts (contr.treatment, using the first alphabetical level as the reference category).

  • Handling of Numerically Coded Categorical Variables: When group memberships are recorded using numbers such as 1, 2, 3, behavior depends on the module:

    • ANOVA (afex) and LCA (poLCA): Numeric factor and item columns are automatically coerced to categorical factors (preventing the common error of fitting a 1-df linear slope across discrete group codes).
    • lm, glm, lmer, brms, glmnet, bart2: Numeric columns are treated as continuous quantitative predictors by default. To treat a numeric group code as a categorical factor, either wrap it as factor(Group) in the Formula box or format its values as text strings (e.g., "G1", "G2") in Excel.

Two-Stage Stealth Variable Aliasing (DOCRVAR & ZVAR)#

Standard R formula parsers throw syntax errors when column names contain spaces, parentheses (), slashes /, hyphens -, percent signs %, leading digits, or multibyte Unicode characters. DocR reconciles unrestricted Excel headers with strict R formula parsing via a two-stage stealth aliasing pipeline:

  1. Stage 1 — VBA ⇔ API Stealth Substitution (DOCRVAR0001, DOCRVAR0002, ...):

    • Across all modules, immediately before JSON serialization, VBA maps every column name to a collision-free internal identifier (DOCRVAR0001, DOCRVAR0002, ...), replacing variable names inside formulas, post-hoc specifications, hypothesis strings, and custom arguments longest-name-first with token-boundary checks (SafeReplaceVariable).
    • Upon receiving R's response, RestoreAlias() restores all internal IDs back to the exact original Excel column names across monospace text summaries (dynamically recalculating character display widths to preserve decimal alignment), structured output tables, and embedded SVG axis/legend labels.

  2. Stage 2 — brms Pre-Compiled Cache Normalization (ZVAR1, ZVAR2, ...):

    • Inside the brms module, variables appearing in standard formulas are further normalized in order of appearance to ZVAR1, ZVAR2, ... Consequently, whenever a model's structural form and distribution family match one of the container's 16 pre-compiled Stan C++ model binaries, brms reuses the compiled binary regardless of column names or dataset, reducing the typical 30–60 second C++ compilation time to zero.
Warning

Important Exception When Writing bf() or mvbind() Directly in brms When a brms Formula begins with bf(...) (for example, non-linear curve models or distributional submodels), Stage 2 ZVAR normalization and pre-compiled cache lookup are bypassed (is_bf = TRUE). Furthermore, because Stan internally concatenates and strips underscores/characters from response and parameter names inside mvbind() and multi-part bf() specifications, we strongly recommend using clean ASCII alphanumeric Excel column names (e.g., score, time, group, ID) without spaces or symbols whenever using bf() or mvbind() (and likewise avoiding spaces or arithmetic operators inside factor level labels referenced in brms Hypothesis Testing).

Automated Out-of-Sample Prediction (brms & BART)#

Bayesian (brms) and Bayesian Additive Regression Trees (bart2) integrate model estimation and out-of-sample forecasting into a single execution pass:

  1. Append new rows at the bottom (or anywhere) of your Excel table in which only the outcome cell Y is left blank while all predictor columns X (and any random-effect grouping IDs) are populated.
  2. Check Output Predictions & Residuals in the analysis dialog and click Run.

  3. The backend automatically partitions the dataset:

    • Training Set (df_train): Estimates model parameters exclusively on rows where both Y and X are observed.
    • Prediction Test Set (df_test): Evaluates the posterior predictive distribution on rows where Y is blank and X is populated (using fitted(..., allow_new_levels = TRUE) in brms so unseen cluster IDs can also be predicted, and test = df_test in BART).
  4. In the [ Predictions and Residuals ] worksheet table, posterior predictive means (Fitted) and 95% credible intervals (CI_Lower, CI_Upper) are reported alongside each case's original Row number (Residual is recorded as NA for test rows).

Plotting Model-Adjusted Marginal Effects Rather Than Raw Group Means#

In multiple regression, generalized linear models, and mixed-effects models, plotting raw bivariate scatterplots or unadjusted group averages can be misleading because confounding covariates and subject-level random effects remain uncontrolled. DocR automatically generates model-adjusted marginal effect and estimated marginal mean plots tailored to each statistical framework:

  • lm / glm / lmer: Uses ggeffects::ggpredict() to plot predicted values and 95% confidence intervals for each focal predictor while holding non-focal continuous covariates at their sample mean (or categorical covariates at their reference level). Crucially, in glm (logistic, Poisson, and ordinal logistic regression), predictions are automatically back-transformed via the inverse link function onto intuitive natural scales—such as predicted probability (0–100%) or expected counts—rather than opaque log-odds.
  • ANOVA (afex): Uses ggeffects::ggemmeans() (calling emmeans internally) to plot Type III Estimated Marginal Means (EMMs) and 95% confidence intervals, properly adjusting for unequal cell sizes and other experimental factors.
  • Bayesian (brms): Combines posterior conditional-effect plots (brms::conditional_effects(), with 95% credible intervals) and MCMC convergence diagnostics (Trace Plots and Posterior Density Plots) in a unified multi-panel display.
  • BART (bart2): Automatically renders a Relative Variable Importance bar chart, 1D Partial Dependence Plots (1D PDP; with ±1.96 posterior SD bands) for every predictor, and 2D Interaction Heatmaps (2D PDP) across pairs of the top 3 most important predictors.

  • Regression Diagnostic Plots & Multicollinearity Diagnostics (VIF):

    • In lm, glm (excluding cumulative), and lmer, DocR automatically appends Residuals vs Fitted (with a red LOESS smoothing curve in lm/glm to check homoscedasticity and linearity) and Normal Q-Q plots (to inspect residual normality).
    • Furthermore, starting in v1.9.0, whenever a model in lm, glm (including cumulative), or lmer contains 2 or more predictor terms, performance::check_collinearity() runs automatically and appends === Variance Inflation Factor (VIF) === (reporting VIF, 95% CI, standard-error inflation factor, and Tolerance; or generalized GVIF for multi-level categorical factors) directly beneath the model summary.

1.6 Common Specifications for Post-Hoc Multiple Comparisons (emmeans & Holm Adjustment)#

In ANOVA (afex) (when Run Post-Hoc Tests (Holm) is checked) and in lm, glm, lmer, and brms (when terms are entered on the Post-hoc tab under Post-Hoc Tests (emmeans)), DocR performs pairwise multiple comparisons on estimated marginal means using the emmeans package (pairs(em, adjust = "holm")).

  • p-Value Multiplicity Adjustment: Holm Step-Down Procedure (adjust = "holm"):

    • All frequentist pairwise comparisons standardize on adjust = "holm" (the Holm–Bonferroni step-down method). Holm's procedure shares the exact same minimal statistical assumptions as the classical Bonferroni correction—strictly controlling the family-wise Type I error rate (FWER) without requiring normality, equal variances, or balanced sample sizes, and remaining valid across repeated-measures factors—while being uniformly more powerful (less overly conservative) than Bonferroni, making it a widely recommended standard across psychology, medicine, and the behavioral sciences.
    • Note for brms (Bayesian models): Rather than frequentist p-values, emmeans summarizes the posterior distribution of each pairwise contrast using the posterior median (estimate) and 95% Highest Posterior Density interval (lower.HPD, upper.HPD). Substantive differences are supported when the 95% HPD interval excludes 0.

  • Post-hoc Tab Specification Syntax (One Specification per Line):

    • Main-Effect Pairwise Comparisons: Group (compares all level pairs of Group)
    • Simple Main Effects: Group | Time (performs pairwise comparisons among levels of Group separately within each level of Time; also valid for categorical × continuous interaction models)
    • All-Cell Interaction Comparisons: Group : Time (performs all-pairs comparisons across every Group × Time cell combination)
  • Automatic factor() Stripping Fail-Safe: If a user writes factor(Group) in the Formula box and inadvertently enters factor(Group) or as.factor(Group) in Post-Hoc Tests (emmeans), an API regular-expression filter (strip_factor_wrapper) automatically strips the wrapper and evaluates ~ Group cleanly without syntax errors.

2.1 Descriptive Statistics & Data Overview — Describe (psych)#

Backend & Statistical Specifications#

  • Ribbon / Dialog / Endpoint: Descriptives (describe) / Data Overview (Descriptive & Distribution) — POST /describe (psych::describe(df) & ggplot2)

  • Computed Summary Indices ([ Descriptive Statistics ]):

    • vars (variable index), n (valid non-missing observations), mean (arithmetic mean), sd (sample standard deviation), median (sample median), trimmed (10% trimmed mean excluding the top and bottom 10% extremes), mad (median absolute deviation scaled by 1.4826 for normal consistency), min (minimum), max (maximum), range (max - min), skew (skewness), kurtosis (excess kurtosis centered at 0 for a normal distribution), and se (standard error SD / sqrt(n)).
  • Graphical Output: Relative-density histogram (after_stat(density), default bins = 30, fill steelblue) overlaid with a red kernel density curve (geom_density()). When multiple variables are selected simultaneously, plots are arranged via facet_wrap(~ Variable, scales = "free") so each variable is rendered on its own native axis scale.

Automated Preprocessing & Safeguards (Under the Hood)#

  • Automatic Numeric Recoding of Categorical Columns for Plotting: Passing text columns directly to a histogram normally triggers a type error in R. During plot generation only, DocR temporarily maps non-numeric columns via as.numeric(as.factor(x)) (1, 2, 3, ...), enabling immediate visual inspection of categorical frequency balance without manual dummy coding.
  • Multi-Variable Fixed-Axis Override Protection: Manual settings for Number of Bins:, Minimum Value:, and Maximum Value: take effect strictly when a single variable is selected for detailed inspection. Whenever 2 or more variables are selected simultaneously, both the UI and API automatically enforce Auto-optimize bins and range (scales = "free", bins = 30) so variables measured on incompatible units never squash one another onto a shared axis. Furthermore, single-variable Minimum Value: / Maximum Value: bounds zoom via coord_cartesian(xlim = ...) rather than filtering out observations, preventing boundary distortion in the kernel density estimate.

Advanced & Custom Syntax Recipes#

  • Pre-Parametric Distribution Screening: Substantial divergence between mean and trimmed (10% trimmed mean), or extreme shape values (|skew| > 2, |kurtosis| > 7), provides objective justification for applying logarithmic transformation log(y), switching to robust Bayesian regression (student family in brms), or choosing spearman / biweight in Correlation.
  • Zooming Past Extreme Outliers on a Single Variable: If a single extreme outlier compresses the main body of a histogram into a single bar, select that variable alone, uncheck Auto-optimize bins and range, and enter an upper cap in Maximum Value: (leaving Minimum Value: blank keeps the lower bound automatic) to inspect the core distribution clearly.

2.2 Correlation Analysis — Correlation (correlation)#

Backend & Statistical Specifications#

  • Ribbon / Dialog / Endpoint: Correlation (correlation) / Correlation Analysis (cor) — POST /cor (correlation::correlation() in the easystats ecosystem + BayesFactor when Bayesian mode is enabled)

  • Correlation Estimators (Correlation Method:):

    • pearson (default): Pearson's product-moment correlation r (linear, parametric)
    • spearman: Spearman's rank-order correlation ρ (monotonic relationships, ordinal scales, outlier-resistant)
    • kendall: Kendall's tau rank correlation τ (robust in small samples or datasets with frequent ties)
    • biweight: Tukey's biweight midcorrelation (M-estimation-based robust correlation down-weighting extreme outliers)
    • distance: Distance correlation (detects both linear and arbitrary non-linear / non-monotonic dependence; equals 0 if and only if variables are statistically independent)
  • Multiplicity Adjustment (p-value Adjustment:): holm (default), bonferroni, fdr (Benjamini–Hochberg false discovery rate control), or none (unadjusted).

  • Additional Estimators:

    • Calculate Bayesian indices (BF & 95% HDI) (bayesian = TRUE): Computes the Bayes Factor (BF10) and 95% Highest Density Interval (95% HDI) of the posterior correlation for each pair.
    • Calculate Partial Correlation (partial = TRUE): Estimates pairwise partial correlations statistically controlling for all other variables included in the selection.
  • Output Format ([ Correlation Matrix (Edge List) ]): Rather than a sparse upper-triangular matrix, results are returned as a tidy 1-row-per-pair edge list (Parameter1, Parameter2, r / rho / tau, 95% CI, t / S, df, p, n_Obs).

Automated Preprocessing & Safeguards (Under the Hood)#

  • Bulletproof NA-Preserving One-Hot Dummy Expansion: When Auto-include factors (dummy-coded) (enabled by default) is checked, every level of a text/categorical column is expanded into a binary 0/1 indicator <Variable>.<Level> (e.g., Gender.Female, Gender.Male). Naive dummy-coding utilities often miscode blank cells as 0, biasing correlations; DocR uses ifelse(df[[col]] == lvl, 1, 0) so rows originally missing (NA) remain strictly NA after dummy expansion, guaranteeing exact pairwise deletion and accurate n_Obs counts.
  • Practical Advantages of Edge-List Output: Even across dozens of variables, Excel's native AutoFilter and Sort tools can immediately isolate pairs with p < 0.05 ordered by |r|, and the table can be imported directly as an edge table into network visualization tools.

Advanced & Custom Syntax Recipes#

  • Reporting Positive Evidence for "No Correlation" (Bayesian Correlation): A frequentist p > 0.05 merely fails to reject the null hypothesis and never proves absence of association. By checking Calculate Bayesian indices (BF & 95% HDI), obtaining BF10 < 0.33 (< 1/3) provides positive quantitative evidence that the null hypothesis (zero correlation) is more than three times as probable as the alternative given the data.
  • Pre-Regression Collinearity & Confounding Screening: Run candidate predictors once as marginal correlations (partial = FALSE) and once with Calculate Partial Correlation (partial = TRUE) to distinguish spurious bivariate associations driven by shared confounders from direct conditional links.

Backend & Statistical Specifications#

  • Ribbon / Dialog / Endpoint: ANOVA (afex) — POST /anova (afex::aov_car())

  • Forced Factorization of All Factors to Prevent Regression Misinterpretation: Even if experimental conditions are coded numerically as 1, 2, 3, every factor and Subject ID on the right-hand side is coerced via as.factor() on the backend—structurally preventing the classic R aov() pitfall of miscomputing a 3-group factor as a 1-df linear trend.

2.7 Regularized Regression (Lasso / Ridge / Elastic Net) — Elastic Net (glmnet)#

Backend & Statistical Specifications#

2.9 Bayesian Additive Regression Trees — BART (dbarts::bart2)#

Backend & Statistical Specifications#

  • Ribbon / Dialog / Endpoint: Bayesian Additive Regression Trees (bart2) — POST /bart (dbarts::bart2(..., keepTrees = TRUE), pdbart(), pd2bart())
  • Statistical Algorithm: Nonparametric Bayesian ensemble machine-learning model that places regularizing priors over a sum of shallow decision trees and uses backfitting MCMC to automatically capture non-linear response surfaces and high-order interactions—combining strong resistance to overfitting with full posterior predictive uncertainty intervals.

  • Automatic Outcome Y Task Detection:

    • Numeric Y: Continuous Regression BART — Outputs Pseudo R-squared (squared correlation between observed Y and posterior predictive mean), RMSE, and posterior residual SD Posterior Sigma.
    • 2-level text/categorical Y: Binary Probit Classification BART — Automatically recodes Y to 0/1, fits probit BART, and outputs classification Accuracy (0.5 probability threshold) alongside posterior event probabilities (categorical outcomes with 3+ levels are rejected with a clear validation message).
  • Default Hyperparameters: Number of trees n.trees = 100 (GUI initial value), n.chains = 4, n.samples (Total Iterations) = 2000, n.burn (Warmup) = 1000 (1,000 post-burn-in draws retained per chain = 4,000 total posterior draws), Cores = 4.

    • Relative Variable Importance (%): Table and horizontal bar chart showing each predictor's posterior mean share of tree-splitting rules (summing to 100%).
    • 1D Partial Dependence Plots (pdbart): Marginal non-linear effect curve (posterior mean ± 1.96 SD credible band / error bars) for every predictor marginalizing over all other predictors.
    • 2D Partial Dependence Plots (pd2bart): Pairwise 2D interaction heatmaps across all pairs of the top 3 most important predictors.

Automated Preprocessing & Safeguards (Under the Hood)#

  • Missing Indicator Method (Missing Indicator Method (Keep), Default):

    • To train on real-world datasets containing missing predictor values X without discarding incomplete cases, DocR automatically performs two steps:

      1. Numeric predictors: Appends a binary missingness indicator column <Var>_isNA (1 if missing, 0 if observed) to the model formula and imputes missing cells in <Var> with the column median.
      2. Text / categorical predictors: Converts missing cells into a dedicated "Missing" factor level.
    • This retains 100% of training rows while enabling tree splits to exploit informative missingness (Missing Not at Random [MNAR] patterns) directly as predictive signal.
  • dbarts Test-Data Deletion Bug Safeguard: Internally, dbarts::bart2 passes test through model.frame(), which silently drops every test row whose outcome column Y is NA. DocR isolates blank-Y rows into df_test and injects a temporary placeholder 0 into df_test's outcome column prior to calling bart2(), guaranteeing complete out-of-sample posterior means and 95% credible intervals (2.5%–97.5% quantiles) for all blank-Y rows.

Pairwise deletion outputs all Row numbers (leaving all-missing rows blank), while listwise deletion records the exact Row indices of complete cases, preventing row misalignment when joining scores back to the original table.

Advanced & Custom Syntax Recipes#

  • Determining the Optimal Number of Factors: On an initial pass, inspect the Scree Plot for eigenvalues exceeding 1.0 (Kaiser–Guttman criterion) and the scree inflection point (elbow), alongside EFA fit indices (RMSEA < 0.08 and TLI > 0.90) across candidate factor counts.
  • Scale Purification & Downstream Modeling: Drop items in [ Item-Level Reliability ] whose Alpha if dropped substantially exceeds the current subscale α or items with weak primary loadings (< .35) / heavy cross-loadings, re-run with Output Factor Scores checked, and copy the resulting factor scores into lm or brms as latent-proxy predictors or outcomes.

2.11 Structural Equation Modeling & Confirmatory Factor Analysis — SEM / CFA (lavaan)#

Backend & Statistical Specifications#

  • Ribbon / Dialog / Endpoint: SEM / CFA (lavaan) — POST /sem (lavaan::sem(model = syntax, data = df, missing = ...) & semPlot::semPaths())

  • Estimator & Missing-Data Treatment:

    • Maximum Likelihood (ML) estimation by default.
    • Default missing-data handling: Full Information ML(FIML) (missing = "fiml") — Directly maximizes the casewise log-likelihood across all observed variables under Missing at Random (MAR) without discarding partially incomplete respondents (switchable in the UI to Listwise Deletion, missing = "listwise").

  • Statistical & Graphical Outputs:

    • Complete summary(fit, fit.measures = TRUE, standardized = TRUE): Chi-square goodness-of-fit test (χ², df, p), CFI, TLI, RMSEA (with 90% confidence interval), SRMR, AIC, and BIC.
    • [ Parameter Estimates (Table) ] (parameterEstimates): Unstandardized est, se, z, pvalue, 95% CI (ci.lower, ci.upper), latent-standardized std.lv, and completely standardized estimates std.all.
    • Standardized Path Diagram (semPaths): Tree-layout LISREL-style vector SVG diagram labeled with completely standardized path coefficients (whatLabels = "std").

Automated Preprocessing & Safeguards (Under the Hood)#

  • Decluttered Path Diagram Defaults: Out-of-the-box semPaths draws residual variance self-loops and intercept triangles on every manifest indicator, rendering multi-item models illegible. DocR enforces residuals = FALSE, intercepts = FALSE so only latent constructs, manifest items, primary causal/correlational paths, and standardized coefficients are cleanly rendered—ready for immediate Convert to Shape polishing in PowerPoint or Excel.
  • Full-Width & Non-Breaking Space Sanitization: Ideographic full-width spaces (U+3000) and non-breaking spaces (U+00A0) inadvertently pasted from web pages, documents, or AI chat assistants into Model Syntax (lavaan style) are automatically normalized to standard ASCII spaces prior to calling lavaan.

Advanced & Custom Syntax Recipes#

Models can be assembled interactively by double-clicking variable names and operator buttons (=~, ~, ~~, +), or written using full lavaan syntax—including parameter labels, defined indirect mediation effects (:=), equality constraints, and higher-order factors:

r
# 1. Confirmatory Factor Analysis (CFA) + Structural Regression Model (SEM)
  WorkplaceSupport =~ Sup1 + Sup2 + Sup3
  JobSatisfaction  =~ Sat1 + Sat2 + Sat3
  TurnoverIntent   =~ Turn1 + Turn2 + Turn3

  # Structural regression paths
  JobSatisfaction ~ WorkplaceSupport
  TurnoverIntent  ~ JobSatisfaction + WorkplaceSupport

  # Correlated residual uniqueness (when theoretically justified)
  Sup1 ~~ Sup2
r
# 2. Mediation Analysis: Estimating & Testing Indirect (a * b) and Total Effects
  # Label paths a, b, c and define indirect/total parameters via :=
  M ~ a * X
  Y ~ b * M + c * X

  indirect := a * b
  total    := c + (a * b)

2.12 Latent Profile Analysis & Latent Class Analysis — LPA / LCA (tidyLPA / poLCA)#

Backend & Statistical Specifications#

  • Ribbon / Dialog / Endpoint: Latent Variable Models (LPA/LCA) — POST /latent

    • Continuous Indicators — Latent Profile Analysis (Continuous) (LPA): tidyLPA::estimate_profiles() (Gaussian finite mixture modeling via the open-source mclust EM algorithm)
    • Categorical Indicators — Latent Class Analysis (Categorical) (LCA): poLCA::poLCA() (polytomous multinomial latent class modeling via hybrid EM + Newton–Raphson estimation)

  • Automated Class Enumeration & Optimal Model Selection:

    • Fits every candidate class count from Min Classes (default 2) through Max Classes (default 5) in a single run and outputs the complete model-comparison table [ Fit Indices ] (AIC, BIC, Entropy, prob_min, n_min, etc. for LPA; AIC, BIC, likelihood-ratio Gsq, and Entropy for LCA).
    • Automatically selects the class count k* minimizing the Bayesian Information Criterion (BIC) as the optimal model, and outputs class-specific parameter estimates, casewise [ Class Memberships ] (Subject, Class), and the vector SVG profile / conditional response-probability plot for that optimal solution.

  • LPA Variance–Covariance Parameterizations (LPA Model (Variance-Covariance)):

    • 1 (Default recommended — EEI): Equal variances across classes and within-class covariances fixed to 0 (most parsimonious and numerically stable profile model)
    • 2 (VVI): Varying variances across classes, within-class covariances fixed to 0
    • 3 (EEE): Equal variances and equal covariances across classes
    • 6 (VVV): Varying variances and varying covariances across classes (unconstrained model suited for large samples)
    • (Note: Per tidyLPA specifications, model numbers 4 and 5 require an external commercial Mplus installation; with DocR's built-in open-source mclust engine, select 1, 2, 3, or 6.)

Automated Preprocessing & Safeguards (Under the Hood)#

  • Automatic Positive-Integer Recoding for poLCA: Standard poLCA halts with an error whenever inputs contain 0/1 binary indicators or text strings ("Yes" / "No"), accepting only positive integers 1, 2, 3, .... DocR automatically transforms arbitrary strings and 0/1 columns via as.numeric(as.factor(x)) into clean 1-indexed category integers.
  • Multi-Start Local-Maxima Protection & Custom Relative Entropy in LCA: Because LCA log-likelihood surfaces exhibit local maxima, DocR runs nrep independent random starts per class count (LCA Replications (Random Starts), default 10; increase to 30–50 for complex models) and retains the global maximum-likelihood solution. In addition, DocR computes normalized Relative Entropy—omitted by base poLCA—from the N × K posterior membership matrix P via Entropy = 1 - sum(-P * log(P)) / (N * log(K)) and appends it to [ Fit Indices ] (values near 1.0, typically > 0.80, indicate crisp class separation).
  • Optional Z-Score Standardization in LPA: Standardize Data (Z-Score) (checked by default) centers and scales continuous indicators measured on disparate units (e.g., annual income, age, and Likert scores) to mean 0 and SD 1 prior to profile extraction.

Advanced & Custom Syntax Recipes#

  • Extracting a Specific Theoretical k-Class Solution (e.g., 3 Classes): If substantive theory calls for inspecting class memberships and profile plots for a specific class count other than the minimum-BIC solution (for example, k = 3), enter the same integer in both Min Classes = 3 and Max Classes = 3 and run.
  • Two-Step Segmentation & Downstream Group Analysis: Join the Class column from [ Class Memberships ] back to your Excel dataset via Subject ID (For Output) to use the discovered latent typology directly as a grouping factor in ANOVA, GLM, or Text Mining.

2.13 Japanese Text Mining — Text Mining (RMeCab)#

Note

Because this module is engineered specifically around the Japanese morphological analyzer MeCab (mecab-ipadic-utf8 dictionary) for unsegmented Japanese text, its menu entry (テキスト分析) is displayed on the DocR > Methods ribbon only when Language is set to Japanese.

Backend & Statistical Specifications#

  • Endpoint / Core Function: POST /textmining — RMeCab::docDF(..., type = 1) (tokenizes Japanese text and lemmatizes inflected words to their dictionary base forms to construct a document–term frequency matrix)
  • Target Part-of-Speech Filter (POS Filter): Defaults to 名詞 (Noun), 形容詞 (Adjective), and 形容動詞 (Adjectival Verb), with optional checkboxes for 動詞 (Verb), 副詞 (Adverb), and 感動詞 (Interjection), retaining terms meeting the minimum frequency threshold (default min_freq = 5).

  • Four Analytical & Visual Outputs:

    1. Term Frequency Table & TF-IDF Characteristic Word Scores (when an Attribute column is specified and TF-IDF is enabled): Across N attribute groups and df groups containing a term, computes smoothed inverse document frequency idf = log(N / df) + 1 and tf * idf, outputting each word's most characteristic group (Top_Attribute) and TF-IDF_Score sorted descending.
    2. Word Cloud (wordcloud::wordcloud): Plots up to the top 100 frequent terms horizontally sized by frequency using the RColorBrewer Dark2 palette.
    3. Co-occurrence Network (igraph): Computes the term co-occurrence count matrix C = t(X) %*% X (zeroing the diagonal) from the document–term matrix X, plots an undirected weighted network of edges above the specified quantile threshold (default 0.90 = top 10% strongest co-occurring pairs), and outputs the [ Co-occurrence Network Edge Weights ] edge list (Word 1, Word 2, Co-occurrence Count).
    4. Correspondence Analysis (ca::ca) (when an Attribute column is specified and Correspondence Analysis is enabled): Performs correspondence analysis on the term × attribute contingency table, outputting inertia (explained variance) summaries and a 2D chi-square distance biplot (at least 3 attribute levels are recommended to render a 2D biplot).

Automated Preprocessing & Safeguards (Under the Hood)#

  • On-Demand Dynamic Compilation of MeCab User Dictionaries: To prevent domain-specific compounds, product names, or technical terms (e.g., 生成AI, カスタマーサクセス, 認知行動療法) from being split into fragments, terms entered in the User Dictionary box are written to a temporary CSV with high priority (cost = -30000, 名詞,一般), compiled on the fly via /usr/lib/mecab/mecab-dict-index into a binary user.dic, applied to RMeCab, and cleaned up immediately afterward.
  • Automatic Single-Character Kana Noise Removal: Single-character hiragana and single-character katakana tokens (^[ぁ-んア-ン]$) arising from grammatical particle fragments or conversational fillers are automatically filtered out on the backend without requiring manual stop-word entry.

  • Co-occurrence Aggregation Unit Rule (Attribute Blank vs. Specified):

    • When Attribute is left blank: Each individual Excel row (1 survey response) is treated as 1 document, so the co-occurrence network captures word pairs used together within the same response (recommended when inspecting overall open-ended co-occurrence structure).
    • When an Attribute column is specified: Responses are concatenated within each attribute level to enable attribute-level TF-IDF and Correspondence Analysis; consequently, co-occurrence counts are also aggregated at the attribute-group level.
